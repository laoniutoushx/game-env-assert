# 环境质量根因与本轮修复

本轮完成工程诊断与一次本地修复，尚未达到概念图 90% 的视觉目标。没有新增 Meshy 任务，新增消耗 0 积分；此前累计 390/800，剩余 410。

## 结论与证据

问题来自几何、资产制作、材质导入和布局的叠加，不能单纯归因于 Godot 渲染能力。当前 Forward+ 在 RTX 3060 上正常运行，导入的 GLB 保留了贴图和切线。

|问题|诊断证据|本轮处理|
|---|---|---|
|旧石板受光发黑|分别关闭阴影、关闭法线贴图、替换灰材质仍存在；检查发现顶面三角形绕序与外向法线不匹配|修正顶面绕序，并生成切线；水面同类绕序错误一并修复|
|旧程序网格缺少切线|石板使用法线贴图但程序生成网格未生成切线；导入 GLB 则已有切线|对修复后的石板生成切线，检查 17 个可见旧石板|
|远处地面和道路纹理跳动、细节混乱|31 个旧 JPG 导入配置关闭 mipmap；Meshy 内嵌纹理已有 mipmap|开启旧纹理 mipmap，标记法线图导入，使用各向异性过滤与 4× MSAA|
|性能与画面比较条件不一致|旧 canvas_items 拉伸下，逻辑视口 1421×736 时曾实际输出 3840×1988|固定 viewport 拉伸和实际输出，并将实际像素尺寸写入性能记录|
|最低档植物轮廓损失|约 762 万三角形母版被逐级减至 1.2 万，减面约 99.84%，没有重烘焙|从母版直接生成蕨类 219999、灌木 300000 三角形版本，重烘焙切线法线；近处使用修复版|
|植物辨识度低|母版与中档版本整体轮廓相近，母版本身也存在均质叶团；花并不因增加面数而清晰|增加独立三维草叶、白雏菊、黄花、粉花，配合蕨类、灌木及少量 Fab 资源|
|UV 与贴图有效细节不足|树木 UV 三角形面积总和从母版约 .262 降至 8 万面版 .096；灌木从 .518 降至 1.2 万面版 .144；原法线变化较弱|保留可用 UV，重烘焙法线；没有把“贴图分辨率高”作为质量保证|
|光照和层次混成一片|恒定环境补光、统一植被染色、植被重复叠加以及根节点非等比缩放|使用天空环境与定向暖光、天空反射和适量 SSAO，区分树皮与叶片响应；移除旧密集散布，改为成簇布局，取消植物非等比拉伸|

UV 面积总和不等于实际纹理占用率，不能据此证明不存在重叠。检查未发现足以解释整场景问题的大规模退化 UV；问题更接近碎片化 UV、减面与源资产细节不足，而非所有模型 UV 全部错误。

Godot 使用顺时针正面，参见 [ArrayMesh 官方说明](https://docs.godotengine.org/en/stable/classes/class_arraymesh.html)。旧补光与水面自发光掩盖了部分几何错误；修复光照时才暴露出来。

## 采用的实现

- 主入口：`../quality_round.tscn`；冻结旧版：`../quality_baseline.tscn`。
- 修复植物以 140/110 屏幕像素阈值切换高、中档，带迟滞，避免距离边界来回切换。全部仍是空间中的三维几何，不是整株面向相机的广告牌。
- 叶片使用法线、粗糙度、适量背光；草与花拥有真实茎、叶和花瓣。源模型仍使用合并图集，尚未完成精细树皮/叶片材质分区。
- 石板恢复正确受光，重新调整偏亮的旧石板色值；水面取消自发光，用粗糙度变化形成湿润响应。
- 资产场景和条目：`../quality_assets/catalog.json`。生成与烘焙脚本保留在本目录，母版未覆盖。

## 试验后未采用

石板重新展开 UV 的版本仍有大量碎片，未明显改善可见效果，最终保留原 UV 修复版。初次高低模重叠 AO 烘焙过暗，改为低模单独 AO 后再少量混合。ReflectionProbe 试验出现退出时纹理资源泄漏，移除后使用天空反射。早期失败试验日志保留供追溯，最终验收以最新时间戳日志为准。

## 验证与查看

打开 [前后对照页面](review.html)、[主视角](all_top.png)、[侧俯视](all_side.png)、[近景](all_close.png)。分项截图是诊断实验，部分早期参数不同于最终合成结果。

固定 1421×736、Forward+、RTX 3060、4× MSAA，预热 6 秒后记录 600 帧，轨道旋转并改变俯角 10–60 度和相机尺寸 7–15。最新数值以 [benchmark.json](benchmark.json) 为准；最终复测 P95 为 17.371 ms，中位数 16.670 ms。旧测试实际输出尺寸不稳定，不能将两者数值直接解释为性能提升比例。

`smoke.gd` 已通过相机平移/重置、统一根缩放、远近 LOD、独立材质染色、石板切线和绕序检查。该 headless 日志包含系统证书存储读取错误，不属于场景脚本故障。`run_reviews.ps1 -SceneOnly` 用真实 GPU 重新运行三视角、轨道性能、UV 检查与七个独立资产场景检查；脚本会在脚本/着色器错误时失败。

独立资产初检暴露材质生命周期错误；将资产材质配置移至进入场景树之前，并让测试等待渲染更新后，七项资产 GPU 复检全部通过，无 ERROR。最终资产日志为 `reviews_20261031_200339_1.log`；主场景三视角、性能与 UV 对应 `reviews_20261031_200045_1.log` 至 `_5.log`。检查脚本现对所有 `ERROR:` 判失败，而不只检查脚本和着色器编译错误。

运行 Godot 主场景后：右键拖动旋转，WASD/方向键平移，滚轮缩放，R 重置。固定截图不能代替相机移动观察；轨道测试也不能证明任意极端穿入植被的视角全部通过。

## 仍然欠缺

外围森林密度与树冠分层不足，空地较大；道路模块重复、色差和破损细节不统一；弯道接缝、石板厚度及遗迹造型与参考仍有明显差距。部分源植物仍呈均质叶团，新增花草也需要更自然的群落分布。场景保留的紫色发光遗迹属于旧布局内容，并非缺失贴图，但与自然环境风格不统一，后续需按参考范围处理。

因此本轮可以确认技术缺陷已修复一批、可独立运行和检查，但不能确认 90% 还原，也没有用性能通过代替视觉通过。下一轮应优先重做道路模块和外围森林结构，再提升关键植物母版质量，而不是继续无差别增加面数或全局加亮。
