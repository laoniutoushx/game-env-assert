# 从标杆树学习统一资产流程

## 先看实际交付

入口是 `../tree_comparison.tscn`，Godot 打开后按 F6。默认显示新树的风格化 PBR。B 返回新树，1–5 看原来的参考树，F1–F3 换风格。L 换光，Tab 换机位。按住右键用 WASD、Q/E 移动，Home 恢复当前预设机位。F5 开风，F8 检查缩小后的画面。控制面板在画面左上角。

Blender 工程在 `source/broadleaf_editable.blend`。默认 Scene 是整树，另外一张 `Leaf_Texture_Bake_Source` 场景保存叶脉与颜色的可编辑烘焙节点。源文件已打包六张贴图，换目录也能读取。

本轮桌面自动化运行时无法启动。因此初始几何由离线 Blender 工具辅助组装，纹理由 Blender 节点烘焙，**不是手工操作录像，也不是真正手绘贴图**。下面给的是可以人工跟做、修改的步骤。所附图是 Godot 实机截图；没有伪造 Blender 操作截图。运行预览不需要执行任何 Python 制作工具。

## 1. 复制工程与理解层级

1. File > Open 打开工程，再 File > Save As 另存自己的版本。
2. Outliner 中 `01_Trunk_and_Primary_Branches` 是主干与五条补充主枝。
3. `02_Canopy_30_Editable_Clumps` 是三十个可独立选取的叶团。
4. `90_Editable_Form_Guides_NO_EXPORT` 为树冠体积参考，`91_Leaf_Modules_NO_EXPORT` 为单叶模块。它们保持隐藏，不应导出。
5. 在 3D Viewport 打开 Overlays > Statistics。正式检查的是三角面，不是四边面数量。

当前 LOD0：7,144 三角面，360 片叶，每片 16 三角面。较早灰模是 720 片八三角面叶；实机近看轮廓偏尖硬，后来在相同总预算中换成更圆润的叶形。这说明预算应服务剪影，而不是强迫每片叶使用同一个面数。

## 2. 单位、原点与变换

Scene Properties > Units：Metric，Unit Scale 1。Blender 为 Z-up，GLB/Godot 为 Y-up，导出器负责坐标转换。

树根是落地点。物体模式下检查 N 面板的变换；需要调整整体尺寸时先确定高度，再 Ctrl+A > Rotation & Scale。检查的是模型在世界中的实际尺寸，而不只是外层空节点的 Scale=1。

不要在导出后又手动旋转 90°。错误的双重转换经常导致树倒地、法线受光异常。

## 3. 制作自己的单叶模块

Outliner 的漏斗菜单可启用显示器图标，开启模块的显示器/可见性开关。可以先显示 `91_Leaf_Modules_NO_EXPORT`，单独选中一个模块，按小键盘 `/` 进入局部视图研究。

从零跟做的一种方法：

1. Shift+A > Mesh > Circle，在左下操作面板或 F9 中设 16 个顶点。
2. 编辑模式将圆缩放为叶形。长度方向约 0.53m，宽约 0.25m；这是便于观察的模块尺寸，摆到树上时继续缩放。
3. 调整叶尖与叶柄端，使两端收拢；中间保留圆润轮廓。不能只保留三个角。
4. 选边界按 F 填面，再 Face > Poke Faces。中心鼓起约 0.03–0.055m，边缘作轻微弯曲。
5. 检查面朝向，校正正面。保持双面显示，轮廓本身由几何构成。
6. UV Editing 中让叶长对应 V、叶宽对应 U。可以让多片叶有意共享图集，不必为每片叶独占纹理。

这是一片带鼓起的薄叶。近距离若需要更完整的纵向中脊，可增加中间线布线；不能靠高光把一张平面变成有厚度的雕塑。本版叶脉细节主要由法线贴图补充。

## 4. 组成叶团，再组成树冠

从一个模块复制出约十二片叶，改变朝向、长度与倾角。避免所有叶片沿一个平面排成圆盘。每组应有上层、侧向和少量内层叶，叶柄朝向相应枝梢。

选中这些叶，Ctrl+J 合为一个叶团对象。合并对象后，叶片仍是可独立选中的不连接网格：编辑模式把鼠标放在一片叶上按 L，即可选中那片叶，再 G/R/S 调整。

先摆主冠大形，再摆叶团。本版使用五个主冠参考体及三十个次级叶团。复制时留出能看见主要分叉的窗口，外轮廓大小不一，顶部也要有可读的形状。

每改一个方向，都用小键盘 1、3、7 看正、侧、顶，再用中键自由环绕。正面好看、侧面像一叠纸的排布不能通过。

## 5. 法线与顶点色

本版保留的是烘焙好的局部叶团法线，不在运行时按世界网格虚构叶团。

人工重做时可复制一个低分辨率球/椭球到叶团位置作为法线参考：给叶团添加 Data Transfer，选择参考体，Face Corner Data > Custom Normals，使用面插值映射，混合从较小值开始逐步比较。参考体不是可见树冠，也不是实心阴影代理。

保留修改前副本。避免将全树法线完全球形化；过强混合会让叶片变成塑料块。导出前应用需要固定的修改器，并检查法线贴图的切线方向。

Object Data Properties > Color Attributes 中的 `AssetData` 记录辅助数据：

| 通道 | 含义 | 编辑原则 |
|---|---|---|
| R | 局部遮蔽，1=无遮挡 | 温和调整，不直接当成黑色颜料 |
| G | 叶团颜色变化，0.5=中性 | 同组相近，组间略变 |
| B | 叶尖风动权重 | 叶柄低、叶尖高 |

在 Vertex Paint 中编辑这些权重。Godot Shader 读取数据，但不把 RGB 数据当作叶片最终固有色。源材质也不应直接将这些顶点色乘进颜色贴图。

## 6. 贴图与可编辑烘焙源

切换到 `Leaf_Texture_Bake_Source` 场景，选中 `Editable_UV_Bake_Canvas`，打开 Shader Editor。

节点中包含 UV、叶脉数学、Noise、Color Ramp、Bump、Normal Map 烘焙目标与保存的输出图。它们生成的是无直射光的固有色和表面细节。Natural palette alternative 保存了写实色板，另一色板用于风格化底色。

重新烘焙颜色：连接颜色到 Emission，再连 Material Output；创建/选中目标 Image Texture，使其成为活动节点，Cycles > Bake > Emit。完成后 Image > Save As 保存一份新文件。

重新烘焙法线：连接 Bump 到 Principled Normal，Principled 接输出，选择 Non-Color 的目标图，Bake > Normal，Tangent Space。先用小尺寸测试再导出 1024。

本版贴图：

| 文件 | 用途 | 大小/空间 |
|---|---|---|
| leaf_natural_base.png | 自然固有色 | 1024，sRGB |
| leaf_painted_base.png | 风格化烘焙底色 | 1024，sRGB |
| leaf_normal_gl.png | 叶脉法线 | 1024，OpenGL/非颜色 |
| bark_base.png | 树皮固有色 | 2048，sRGB |
| bark_normal.png | 树皮法线 | 2048，非颜色 |
| bark_orm.png | R=AO/G=粗糙度/B=金属度 | 2048，非颜色 |

要继续手绘：在 Krita 打开底色图，Save As 保存自己的 `.kra`，用单独图层画颜色归整和中频笔触，再导出 PNG。不要把固定方向阳光、高光和投影画死在写实底色里。这一步本轮没有代替你制作完成的 `.kra`，不能把节点烘焙称为人工笔触。

## 7. 树干、枝条与根部

主干来自 Poly Haven tree_small_02。原细枝片已移除；补充主枝为真正的管状网格，并根据主干截面位置接入。根部有扩张，未放固定黑圆遮挡接缝。

在网格编辑模式中重点看分叉、接入点和树根。轻微穿插可用于被树皮遮蔽的接头，但露在外面的断面、悬空枝和明显自相交应修整。树皮法线不能掩盖错误剪影。

树干和枝条 UV 不要求全部唯一，但拉伸、图案尺寸与接缝必须可控。本轮保留主干 UV，补充枝条使用展开的 UV；英雄近景仍需人工细修衔接。

## 8. 从 Blender 导出到 Godot

选中主干、补充枝条及三十个叶团，File > Export > glTF 2.0，GLB，Selected Objects，Active Scene，Normals、Tangents、UV 和 Active Vertex Color。

**不要选择参考球、单叶模块或贴图烘焙画布。** 文件中有两张场景，Active Scene 是避免误导出画布的重要设置。

保留对象名称，例如 `LeafClump_00`、`Primary_Branch_00`、`Trunk_Branches_LOD0`。预览场景按节点名记录外部材质覆盖；若改名，应在 Godot 中重新绑定相应节点，不要只看文件能否加载。

Godot Import 面板关闭本资产的 Generate LODs，使用已有的显式几何 LOD。不要修改原场景所共享的导入配置。

## 9. 在 Inspector 检查材质

打开 `tree_style_1_lod_0.tscn`，Model 已允许编辑子节点。选一个 LeafClump，在 Surface Material Override 中打开 `leaves_1.tres`。

`base_map` 为风格化底色，`normal_map` 为 OpenGL 法线，`roughness` 控制实际高光，`normal_strength` 控制叶脉强度，`variation` 控制组间变化，`wind_strength` 默认 0。

树干使用 `bark_1.tres` 的 ORM/PBR 材质。①②叶片共享 `leaf_pbr.gdshader`，③使用 `leaf_toon.gdshader`，两者共享 `leaf_common.gdshaderinc` 输入约定。统一标准不要求树皮与叶片强用一个 Shader。

当前叶片由几何裁出轮廓，未使用透明整团卡片。若后续改用带透明细节的薄面，应使用 Alpha Scissor/Alpha-to-Coverage 并保留阴影检查，不能直接改成排序不稳定的 Alpha Blend。

## 10. 光照排查顺序

先不开风、不开景深/雾，按 G 看灰模，依次检查：剪影、主枝、叶团体积、根部、阴影。

再恢复材质，依次关闭法线、减少 AO、调整粗糙度，每次只动一项。按 L 换中性、午后、阴天，保持同一套材质。关闭太阳时，树只能保留环境补光，不应保留画死的强高光。

三套光照分别保存为 `lighting/afternoon.tres`、`neutral.tres`、`overcast.tres`。打开资源可在 Inspector 中修改 Sun Color、Sun Energy 与 Environment；根节点的 Camera Positions / Camera Targets 数组可修改三个机位，均无需改脚本。

颜色环境补光要选 COLOR，使用 SKY 时必须真正配置 Sky 资源。旧验收台曾选 SKY 却未提供天空，这会使暗面异常黑；调亮贴图并不能解决根因。

## 11. LOD 的正确简化

LOD0 7,144；LOD1 3,778；LOD2 1,010。LOD1 减少完整叶片并适当扩大保留叶的覆盖，避免每片叶都减成三角形。LOD2 为三十个三维低面数叶团加枝干，不是 billboard。

在预览中先手动切同机位，再打开 Auto。参考距离为 14m、28m，有 ±8% 滞回；这是本验收相机的默认值，正式游戏需按屏幕覆盖与 FOV 调整。滞回只减少边界来回切换，不等于消除了可见切换差异。

本版保留几何真实投影，没有启用封闭球体的仅投影代理。未来要优化投影，也必须保留冠间空隙并检查树冠自遮挡。

## 12. 归档与继续改进

用 `review.html` 对照原树、三种风格、不同光照、关灯和连续环绕。视频为 240 个引擎输出帧按 30FPS 编码，不能把它的播放帧率当成游戏性能。

当前工程是可以继续精修的 WIP：树冠饱满度、枝干自然衔接、树皮过渡和人工笔触尚未达到概念图。不要因为通过了面数/材质校验就标记商业成品。

完成自己的版本后，保存 `.blend`、贴图源文件、GLB、材质、验收图及实际性能，再提交 Git。

### 离线复现工具的边界

`tools` 中的 Blender 工具只复现本轮固定拓扑的初始组装/烘焙，不是通用自动美术管线。人工修改后先另存工作副本，不要直接重跑工具覆盖自己的工程；日常跟做使用编辑器操作与手动导出。
